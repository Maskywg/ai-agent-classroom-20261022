02 / PREPARE VERSION TOOLS

先準備 Git，再開始做作品。

新員工報到後，先準備版本工具。這一站完成安裝與登入，等網頁驗收後再保存、發布。

三個名字，各有工作

Git：在電腦上記錄檔案版本。
GitHub：在雲端保存與分享專案。
GitHub CLI：讓 Agent 透過指令協助登入及操作 GitHub。

  1. 先建立 GitHub 帳號，準備好自己的登入方式。
  2. 請已安裝的 Agent 檢查 Git 與 GitHub CLI，缺少才安裝。
  3. 本人依引導完成 GitHub 登入與授權。
  4. 請 Agent 檢查 git --version、gh --version 與 gh auth status，只回報版本及帳號狀態，不輸出憑證。

WHEN YOU GET STUCK

卡關時，讓 AI 看見你遇到的問題。

把問題圈出來，把檔案位置說清楚。附上「正在做什麼、預期結果、實際情況」，AI 才容易找到下一步。

① 截圖標示：把卡住的地方圈出來

  1. 保留問題附近的按鈕與完整錯誤訊息，擷取畫面。
  2. 用截圖工具的標示功能，加上紅框、圈圈或箭頭，指出要處理的位置。
  3. 把圖片拖入對話欄，或用附件按鈕上傳，再補一句具體說明。
  4. 依 Agent 建議逐步操作；若沒有解決，回傳新的畫面與結果。

Mac：按 Shift + Command + 4 選取範圍，點截圖縮圖進入標示。
Windows：按 Windows + Shift + S 選取範圍，開啟截圖通知後用剪取工具的畫筆標示，再儲存或複製貼上。

傳送前遮住密碼、API key 與個人資料。錯誤文字也可以一併複製貼上，方便準確判讀。

我卡在這一步，請看附上的截圖與紅框。
我正在做：【例如：發布網頁】
我原本預期：【例如：按下後開啟網站】
實際發生：【例如：出現錯誤訊息】
請先判斷可能原因，告訴我下一步要操作哪裡。
若畫面資訊不夠，請說明需要補拍哪個範圍，不要猜測看不到的內容。

② 貼檔案路徑：告訴 AI 材料在哪裡

路徑就像檔案的地址。先在檔案管理工具選取檔案，再複製完整路徑，貼到本機 Agent 的對話欄。

Mac / Finder

  1. 開啟 Finder，找到並點選檔案或資料夾。
  2. 按 Option + Command + C 複製路徑。
  3. 回到 Agent，按 Command + V 貼上。

也可按住 Option 再對檔案按右鍵，選「拷貝⋯作為路徑名稱」。快捷鍵要在 Finder 選取項目時使用。

/Users/你的名稱/Desktop/AI練習/活動素材.txt

Windows / 檔案總管

  1. 按 Windows + E 開啟檔案總管，找到檔案或資料夾。
  2. Windows 11：對項目按右鍵 → 選「複製為路徑」（Copy as path）。
  3. Windows 10：按住 Shift 再對項目按右鍵 → 選「複製為路徑」。
  4. 回到 Agent，按 Ctrl + V 貼上。路徑外圍的雙引號可保留。

若找不到選項，可嘗試按住 Shift 再按右鍵，或展開「顯示其他選項」。請選完整檔案路徑，而非只複製所在資料夾的網址列。

"C:\Users\你的名稱\Desktop\AI練習\活動素材.txt"

貼上路徑不等於上傳檔案或自動授權。本機 Agent 需要能存取該位置；一般網頁聊天或雲端 Agent 無法只靠你的電腦路徑讀檔，請改用附件上傳。雲端同步檔案也要先確認已下載到本機。

請讀取以下本機檔案：
【在此貼上完整檔案路徑】
我的目標是：【例如：依這份文字製作網頁】
請先確認檔案是否存在、是否能讀取，簡述內容，先不要修改。
若無法存取，請告訴我需要開啟哪個資料夾、提供附件或完成哪些授權。

官方操作參考：Apple：拷貝路徑名稱 ↗ · Microsoft：檔案總管與右鍵選單 ↗

05 / CONNECT THE DOTS

讓作品有家，讓素材有序。

Git 與 GitHub 登入已在第二站準備完成。現在把驗收過的作品保存、發布，再進入 Google Drive 素材整理。

⑂

GitHub：保存並發布你的作品

Git 是本機版本管理；GitHub 是雲端儲存庫；GitHub CLI 是協助登入及操作的工具。裝好 CLI 不等於已授權 Agent 的外掛。

  1. 請 Agent 確認第二站準備的 Git、CLI 與登入狀態仍可用。
  2. 依引導登入，將專案保存為第一個版本。
  3. 想分享靜態網頁：到 repo 的 Settings → Pages，選擇分支與資料夾後儲存。
  4. 等待部署成功，開啟網址實際驗收。

公開 repo 與公開網頁會讓別人看到內容。上傳前移除帳密、API key 與個人資料。Pages 適合靜態網站。
